# Ray Dashboard integration

Ray exports system and application metrics in Prometheus format. The bridge
collects those metrics and gives Ray Dashboard and Grafana a Prometheus query
API backed by SigNoz. This integration verifies a Ray head and worker without
requiring KubeRay; KubeRay only manages the same Ray processes on Kubernetes.

## Collect Ray metrics

Ray's head Dashboard exposes HTTP service discovery at port `8265`. It tracks
workers as they join and leave, so use it instead of static worker Pod IPs.

```yaml
collection:
  mode: standalone
  extraScrapeConfigs:
    - job_name: ray
      scrape_interval: 15s
      http_sd_configs:
        - url: http://ray-head.ray.svc:8265/api/prometheus/sd
          refresh_interval: 60s
```

For an existing OpenTelemetry Collector, set `collection.mode=existing` and
mount the chart-rendered Collector fragment in that Collector. A chart-owned
collector must run as one replica, unless target allocation or another explicit
sharding mechanism prevents duplicate scrapes.

Set a fixed `--metrics-export-port` on every Ray node. The Ray service
discovery response then contains stable `<pod-ip>:<port>` scrape targets.

## Configure Ray Dashboard and Grafana

Ray Dashboard requires the `ray[default]` installation and a Grafana instance;
the bridge does not host Grafana or import dashboards. Keep bridge API
authentication enabled in production and provide Ray the bearer header as a
JSON-valued environment variable. Store that complete JSON value in a Secret,
not in the workload manifest.

```yaml
apiVersion: v1
kind: Secret
metadata:
  name: ray-prometheus-headers
type: Opaque
stringData:
  headers: '{"Authorization":"Bearer replace-with-the-bridge-token"}'
---
env:
  - name: RAY_PROMETHEUS_HOST
    value: http://prometheus-api-bridge.observability.svc:9090
  - name: RAY_PROMETHEUS_HEADERS
    valueFrom:
      secretKeyRef:
        name: ray-prometheus-headers
        key: headers
  - name: RAY_PROMETHEUS_NAME
    value: Prometheus API Bridge
  - name: RAY_GRAFANA_HOST
    value: http://grafana.grafana.svc:80
  - name: RAY_GRAFANA_IFRAME_HOST
    value: https://grafana.example.com
```

`RAY_GRAFANA_HOST` must be reachable from the Ray head Pod. Set
`RAY_GRAFANA_IFRAME_HOST` to the browser-reachable Grafana URL, and enable
Grafana iframe embedding. Configure a Grafana Prometheus datasource named as
`RAY_PROMETHEUS_NAME`, point it at the bridge, and give it the same
`Authorization` header.

Import the dashboard JSON files generated by the installed Ray version from
`/tmp/ray/session_latest/metrics/grafana/dashboards/`. Keeping dashboard JSON
with its matching Ray release avoids silently using stale metric names or
queries.

Check the Ray Dashboard health endpoints after deployment:

```text
http://<ray-dashboard>:8265/api/prometheus_health
http://<ray-dashboard>:8265/api/grafana_health
```

## Compatibility boundaries

The bridge forwards Ray PromQL unchanged to SigNoz. It does not emulate a full
Prometheus server: `ray metrics launch-prometheus`, Prometheus rules and
alerting, federation, remote write, and the Prometheus targets UI are not
provided. Queries unsupported by the configured backend fail with its normal
Prometheus API error; the bridge does not approximate their result.
